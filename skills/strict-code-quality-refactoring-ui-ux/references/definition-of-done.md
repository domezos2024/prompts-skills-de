# STRICT Definition of Done

Ein Punkt darf nur `[x]` sein mit Nachweis. Sonst offen lassen oder `[!]` Blocker.

- [ ] Relevante Projektbereiche analysiert (PHASE 1)
- [ ] Code-Audit durchgeführt (PHASE 2)
- [ ] Kritische und hochpriorisierte, sicher behebbare Mängel korrigiert
- [ ] Begründetes Refactoring umgesetzt (PHASE 3)
- [ ] UI/UX-Audit durchgeführt (PHASE 4)
- [ ] Erforderliche UI/UX-Verbesserungen implementiert (PHASE 5)
- [ ] Wesentliche Funktionen haben verständliche Fehler- und Erfolgsmeldungen
- [ ] Zustandsänderungen in relevanten Abläufen nachvollziehbar
- [ ] Erfolgreicher Build (oder Umgebung erlaubt es nicht – begründet)
- [ ] Geeignete verfügbare Tests ausgeführt (PHASE 6)
- [ ] Neu entstandene Regressionen behoben
- [ ] Performance geprüft/gemessen oder als nicht messbar begründet (PHASE 7)
- [ ] Zweiter Qualitätsaudit abgeschlossen (PHASE 8)
- [ ] Abschlussbericht erstellt (PHASE 9)
- [ ] Verbliebene Blocker und Einschränkungen eindeutig dokumentiert

**Abschlussregel:** Nicht überprüfte Punkte nie als abgeschlossen markieren.
