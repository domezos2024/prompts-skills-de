# Feature-Opportunity Checklist

Jedes Item: `Pass` | `Fail` | `N/A` + Beweis (Datei/Ticket/Notiz).

## Produktkontext

- [ ] Kernfunktionen inventarisiert
- [ ] Zielgruppe/Personas benannt (belegt)
- [ ] Produktziele / Success-Metrics klar
- [ ] Technische Grenzen und Plattformen erfasst

## Evidenz

- [ ] Nutzerfeedback / Support / Reviews ausgewertet
- [ ] Wettbewerbsbeobachtung nur mit Quellen
- [ ] Vermutungen als Hypothesen gekennzeichnet

## Bewertung (≥10 Kandidaten)

- [ ] Nutzwert (User Impact) scored
- [ ] Aufwand scored
- [ ] Wartungskosten scored
- [ ] Risiko (Tech/Recht/UX) scored
- [ ] Top-3 mit Use Cases dokumentiert

## Umsetzung (1 Kandidat)

- [ ] Scope begrenzt und Rollback definiert
- [ ] Akzeptanzkriterien messbar
- [ ] Tests/UI/Docs geplant und nach Build vorhanden
- [ ] Rest-Roadmap P0–P3 priorisiert

## Anti-Patterns

- [ ] Keine Features nur wegen „Modetrend“
- [ ] Keine unnötige KI-/Komplexitäts-Schicht
